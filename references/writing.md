# 写作：结论、页面描述、层级树排版

## 1. 结论怎么写

一条结论 = **反常识判断 + 可核验证据 + 一句解释**。不要写"它有三个 Tab"这种描述。

### 反例 → 正例（都来自真实项目）

| 反例（描述） | 正例（判断） |
|---|---|
| "它有三个底部 Tab" | "PC 端是独立客户端，不是移动端投屏页：五 Tab + 平台卡片 + 工具工坊，移动端三 Tab 被拆成游戏库 + 详情 + 工具箱" |
| "它有时长充值页" | "它卖的不是会员，是「可暂停时长」：88h ¥9.9 到 1999h ¥89，单价 0.11→0.044 元/时，和移动端的 7/30/60/365 天订阅互不相通" |
| "它有看广告免费加速" | "免费时长被搬到了手机上：PC 端没有广告播放器，只有三步引导去 App 看视频再回 PC 领——PC 是收银台，移动端是留存池" |
| "它有准星工具" | "三个 PC 独有能力：准星覆盖层（Ctrl+F10、多显示器、像素偏移）、修复三件套（Hosts/加速异常/DLL）、平台启动器（Steam/NVIDIA/Epic/EA/罗技/Wallpaper Engine）" |
| "它装了驱动" | "加速内核 = 驱动 + 静态路由表：wxrjsqxyz.sys 常驻，安装目录 10 份按国家拆分的 .route（US 9.5MB、DE 10.2MB），是分流不是全局 VPN" |

### 结论数量与顺序

4–5 条，顺序固定：**产品结构 → 商业模式 → 增长/免费逻辑 → 差异化能力 → 技术底座**。
必须有一条回答"它靠什么赚钱"，一条回答"它真正的竞品是谁"。

## 2. 页面描述的三层写法

每个页面卡片固定四块：路径 / 类型 / 页面说明 / 要点。

- **页面说明**（1–2 句）：这个页面是什么、由哪几块组成、和别的页面什么关系。
- **要点**（3 条起）：
  1. 第一条写**结构事实**（有哪些元素、数字、文案）。
  2. 第二条写**产品意图**（为什么这么设计、在转化链路里的位置）。
  3. 第三条写**异常/限制**（灰的、缺的、点了没反应的、要付费的）。
- **跳转 / 限制**：跳转写"能去哪"，限制写"为什么不能去/有什么门槛"。

示例：

> **路径**：主页右栏 →「时长充值」
> **说明**：浅色 H5，顶部五个卖点，下方四档时长包，右上角导流下载 App。
> **要点**：
> - 88h ¥9.9 / 240h ¥19.9 / 666h ¥49.9 / 1999h ¥89，单价 0.11/0.08/0.07/0.044 元每小时。
> - 用"分钟计费·永久有效·可暂停"替代订阅到期焦虑，1999 小时是拉高客单的锚点。
> - H5，需登录态；支付倒计时 10 分钟；退款入口不在客户端内。

## 3. 层级树排版

用 `text` 代码块，字符固定：`├─`、`└─`、`│`，缩进 4 空格。规则：

- 第一行：`产品名 版本（窗口/分辨率）`。
- 第二层：全局结构（顶栏、Tab、弹窗层、隐藏窗口）。
- Tab 内最多列到三级；同级超过 6 个用"…"收尾，别把 12 张卡片全列出来。
- 弹窗层、隐藏窗口单独成支，不要塞进某个 Tab。
- 每行控制在 60 个字符内，中文按 2 字符算。

## 4. 技术观察怎么写

一行一个维度，格式 `| 维度 | 结论 |`，结论里必须有数字或路径：

- 体积：`892 文件 / 257.7 MB；app.so 12.4 MB`
- 签名：`星宇宙（上海）智能科技有限公司（DigiCert，2024-10 ~ 2027-10）`
- 驱动：`wxrjsqxyz.sys，微软 WHCP 签名，服务 RUNNING`
- 网络：`常连 81.69.128.72:8848（Nacos 默认端口）`
- 缓存：`9 个 hive：user_info / user_login_info / ...`

没有数字的观察不要写（"架构较复杂"= 废话）。

## 5. 产品判断与风险

- 判断 2–3 条，每条一个标题句 + 一段展开，允许有观点。
- 风险清单 ≥ 4 条，**每条必须能落到具体页面/组件**（"准星工具对 ACE/EAC 敏感"而不是"存在合规风险"）。
- 结尾必须写"没做到的部分"：未支付、未开加速、点击无反应、未拿到某页。

## 6. 用词

- 统一"页面 / 弹窗 / 悬浮层 / 隐藏窗口"四个词，不要混用"界面""视图"。
- 数字用阿拉伯数字，价格写 `¥9.90`，时长写 `88 小时`。
- 引用外部信息时写明来源性质，不写"据说"。
